# 制度維護協議
<!-- last-updated: 2026-07-03 | 對象：未來所有 session（含弱模型）。目的：讓制度能安全演化，而不是腐化或膨脹。 -->

制度檔清單：`~/.claude/CLAUDE.md`（全機路由）、`~/.claude/rules/00–40 各檔`、`LESSONS.md`、
各專案的 `CLAUDE.md`（專案事實路由）。

---

## 1. 權限分級

**可自行修改**（改前必備份，見第 3 節流程）：
- 修正失效的路徑、工具名、參數、model 名——改完在該行加註 `(verified YYYY-MM-DD)`。
- 為既有規則新增範例（正例／反例）。
- 追加 LESSONS.md 條目。
- 更新專案 CLAUDE.md 的專案事實（指令、陷阱、權威順序）。

**動之前必須先問使用者**：
- 新增、刪除、或改寫任何硬規則（`~/.claude/CLAUDE.md` 的 1–6 條）。
- 修改升降級門檻或成本姿態（10-DISPATCH 第 4 節與檔頭）。
- 刪除任何制度檔，或把某檔內容大幅重組。
- 修改本檔（40-MAINTENANCE.md）的權限分級本身。

---

## 2. 踩坑教訓寫哪裡

- 通用教訓（任何專案都適用）→ **append** 到 `~/.claude/rules/LESSONS.md`，格式照該檔範例：

  ```
  ## YYYY-MM-DD <一句話標題>
  情境：<當時在做什麼>
  錯誤：<實際發生什麼>
  修正：<怎麼解的>
  建議寫回：<哪個 rules 檔的哪一節；暫無則寫「觀察中」>
  ```

- 專案限定的事實與偏好 → 寫進該專案的 memory（memory 目錄 ＋ MEMORY.md 索引），不要塞進 rules。
- 判斷標準：換一個 repo 還成立的是「教訓」；只對這個 repo 成立的是「memory」。

---

## 3. 每次修改制度檔的固定流程（不可跳）

1. 備份：`cp <file> ~/.claude/rules/backups/<basename>.bak-YYYYMMDD`
2. 修改（用 Edit，最小改動）
3. 更新該檔檔頭的 `last-updated`
4. 自查：重新 Read 全檔，確認改動落地、沒破壞其他段落
5. 驗收（修改超過 5 行、新增／改寫規則、或 diff 未直接呈現給使用者時）：派 fresh-context agent
   用 30-TEMPLATES.md 最後的驗收模板 read-back。作者自查（第 4 步）不能取代這一步。

---

## 4. 精簡時機（防膨脹）

- `LESSONS.md` 超過 30 條或 300 行 → 提議精簡：已升格為規則的條目刪除、同類合併。**動手前問使用者。**
- 其他 rules 檔超過 250 行（LESSONS.md 不適用本行，只適用上一行的門檻）→ 檢查是否有可刪的重複或可合併的段落，提議給使用者。
- 精簡的原則：刪掉的內容若有史料價值，先整份備份再刪。

---

## 5. 發現規則與現實衝突時

例：Agent tool 多了新參數、model 名變了、skill 清單不同了。
- 屬「可自行修改」類 → 立即修（走第 3 節流程），加 `(verified YYYY-MM-DD)`。
- 屬「先問使用者」類 → 本 session 內先照**現實**做（現實優先於過時規則），並回報使用者建議修訂。
