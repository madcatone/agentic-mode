> 蒸餾來源：結構借自 HWDC-2026 課堂 team-kit `fortify-preverify/references/data-flow.md`
> （2026-10-17 讀取），措辭全數重寫、語言中立化；規則編號對應本 kit

## 使用方式

1. 先在下表「不可信輸入來源」中辨識本次 diff 實際出現的來源。
2. 對每個來源，沿「來源 → 轉換 → 驗證／授權 → 輸出／操作」追到 sink，
   再到矩陣找對應列，逐條回答該列的檢查問句。
3. 問句答不出（追不到邊界或設定）＝「需補資訊」；該流向在 diff 中不存在＝「不適用」。

## 不可信輸入來源（source 類型）

| 來源類型 | 語言中立特徵 | 例 |
|---|---|---|
| 請求參數／標頭／cookie | 由呼叫端任意填寫的鍵值 | query/body 欄位、自訂 header |
| 路徑段與查詢字串 | 從 URL 拆出的字串 | route segment、`?next=` |
| 上傳檔案 | 名稱、宣告類型、內容皆由上傳者控制 | 附檔名、MIME、檔案本體 |
| 外部服務回應 | 你不擁有的系統給的資料 | 第三方 API payload、webhook body |
| 資料庫既存值 | 曾源自上述來源、落地後再讀出 | 個資欄位、使用者暱稱 |
| 使用者可控的跳轉目標 | 拿輸入決定下一個位置 | redirect/forward 參數 |
| 訊息佇列 payload | 佇列生產者未必受你控制 | job 參數、事件欄位 |

## 矩陣：流向 × 對應 SEC × 檢查問句

| # | 流向（source → sink） | 對應 SEC | 每格檢查問句 |
|---|---|---|---|
| 1 | 輸入 → HTML／attribute／JavaScript 上下文輸出 | SEC-02 | 實際輸出上下文是哪一種（HTML body／attribute／JS 字串）？該上下文有無編碼或清理策略？有無繞過編碼的路徑（raw 輸出、危險 API）？ |
| 2 | 輸入 → SQL／查詢語句 | SEC-03＋SEC-05 | 值是以參數傳入還是拼接進語句？語句內容可否由輸入改變結構？回傳物件有無依使用者／租戶做存取授權？ |
| 3 | 輸入 → 檔案路徑／檔案操作 | SEC-04＋SEC-09(上傳) | 路徑有無正規化並限制在允許目錄內？有無 `..`／絕對路徑／符號連結越界？上傳有無限制類型、大小與處理成本？ |
| 4 | 輸入 → URL／對外請求／程序引數 | SEC-04＋SEC-13 | 目的地可否被輸入控制（SSRF／open redirect）？有無限制允許的 scheme／host？有無以輸入組 shell 命令？對外呼叫是否走加密傳輸？ |
| 5 | 輸入 → 輸入綁定／持久物件欄位 | SEC-07＋SEC-05 | 綁定白名單是否只含允許修改的欄位？權限／擁有者／狀態是否由伺服器判定？是否直接把持久物件當綁定目標（overposting）？ |
| 6 | 輸入 → 日誌 | SEC-10＋SEC-08 | 值是否經日誌 API 的結構化參數傳入（非串接／插值）？可能含 CR／LF 的值有無先移除或編碼？有無把機密或敏感資料寫進日誌（SEC-01）？ |
| 7 | 輸入 → 回應標頭／Cookie 值 | SEC-11 | 寫入標頭／cookie 前有無驗證並移除 CR／LF？cookie 是否設 HttpOnly／SameSite（邊界為 HTTPS 時含 Secure）？ |
| 8 | 輸入 → regex（pattern 或比對對象） | SEC-12 | pattern 來源是程式碼常數還是輸入？比對不可信輸入時有無設逾時或用無回溯引擎？ |
| 9 | 輸入 → XML 解析／反序列化 | SEC-09 | XML 解析有無停用 DTD 與外部實體？反序列化的型別由誰決定——程式碼宣告還是輸入內容？ |

## 非流動檢查（不依資料流，逐 diff 掃）

| # | 檢查 | 對應 SEC | 檢查問句 |
|---|---|---|---|
| 10 | 秘密進原碼 | SEC-01 | diff 內有無憑證、金鑰、token、密碼或連線字串？占位字串不得判為洩漏，但不得鼓勵硬編碼寫法。 |
| 11 | 部署邊界（先於 7 的 Secure／4 的 TLS 判定） | SEC-11＋SEC-13 | 票面／設計有無交代部署邊界？全程 HTTPS、還是明文本機開發（後者 Secure／SEC-13 記不適用並註記正式部署前補上）？ |

## 追蹤守則

- **真實資料流優先於關鍵字命中**：讀實際呼叫與轉換；關鍵字出現本身不構成 finding。
- **追不到就說追不到**：必要來源或邊界無法追溯 → 「需補資訊」；該流向不存在 → 「不適用」。
- **測試全綠不代替資料流預檢**：測試結果只作佐證，不作免除。
