# fable5 — 用一次強模型 session，把判斷力寫成制度

## 這是什麼操作模式

主對話模型不下場執行，而是作為 advisor／指揮官：與使用者對話、做決策、分派 subagent、整合結論。大量執行（讀大檔、掃 repo、查網頁、批次改檔）一律交給 subagent，主對話只收結論。

這個 skill 打包了建立這套制度的創始 prompt（`reference/GUIDELINE.md`）：拿到一次強模型（Fable／Opus 級）的機會時，不要拿它做日常任務——用它把判斷力外化成弱模型可執行的規則檔，讓之後每一個較弱模型的 session 都因此變強。

## 為什麼需要

agent 協作有三個常見失效：

1. 主對話親自讀大檔／掃 repo，導致 token 洩漏與失焦（context 一滿，最早的使用者指示先被壓掉）。
2. 指示檔案腐化、彼此矛盾，弱模型把過時內容當現況。
3. 自我宣告完成，沒有外部驗證——作者驗自己永遠驗得過。

對策是三支柱：**派工隔離、外部驗證、可執行的判準**。制度目標：**弱模型照制度跑，也能接近強模型的可靠度**。

## 怎麼用創始 prompt

1. 開一個強模型 session（Sonnet 也能跑，但「判斷力外化」的品質與模型等級正相關）。
2. 把 `reference/GUIDELINE.md` 全文作為開場 prompt 貼入，按自己的環境調整敘述（例如把「唯一一次使用 Fable 5」改成你的實際情境）。
3. 讓它自主跑完交付清單 A–G 與收尾四步（對抗審查、read-back、一頁總結、交接）。
4. 產出落在 `~/.claude/`：`CLAUDE.md` 精簡路由＋硬規則，`rules/` 底下診斷、調度、判準、模板、維護、交接信、`LESSONS.md` 各檔。之後每個 session 自動載入。

## 核心原則（不跑創始 prompt 也可以先手動遵守）

- **指揮官不下場**：讀 >200 行或 >3 個檔、位置不明的搜尋、查網頁、改 >2 個檔 → 派 subagent，主對話只收結論與 `檔案:行號`。
- **派工三件套**：目標與動機／驗收條件／回報格式，結尾固定寫「你的最終訊息就是全部回報，沒有人會追問」。
- **驗證不自驗**：作者不簽收自己的產出；程式碼實跑 build／test，文件派 fresh-context agent read-back。
- **升降級有門檻**：小模型錯 1 次直接升級；中階模型同一子任務錯 2 次、帶完整失敗軌跡升級；到頂整理軌跡問人。

## 寫規則檔時的注意

- **讀者是較弱的模型**：規則要具體、可執行、有判準與正反例；抽象要求（「保持高品質」）等於沒寫。
- **產出不可依賴只有強模型做得到的能力**，Sonnet 等級要跑得動。
- **改既有檔案前先備份**；隨做隨寫——session 隨時可能中斷，已落檔的就是全部。
